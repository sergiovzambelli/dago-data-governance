# Threat model

Metodo: STRIDE (Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege).
Aggiornato a ogni PR che aggiunge dati, input, endpoint, integrazioni, dipendenze o permessi. Le minacce non si cancellano: si chiudono.

## Asset
- Dati del kit in `data/`: documenti con dati personali (sintetici), etichette di valutazione riservate.

## Confini di fiducia
_Nessuno ancora (vedi `flussi.md`)._

## Minacce

| ID | Componente | STRIDE | Minaccia | Mitigazione | Stato | PR |
|----|------------|--------|----------|-------------|-------|----|
| T-001 | Repository | I | Segreti committati per errore | `.env` escluso da git | chiusa | chore/kit-data |
| T-002 | `data/` | I | Dati personali o etichette riservate pubblicati su GitHub | rischio accettato dal team: dati sintetici (LEGGIMI del kit), zip già nel repo | accettata | chore/kit-data |
| T-003 | `make data` | T | Archivio zip con percorsi `..` o assoluti (zip-slip) | estrazione con `zipfile` di Python, che li scarta | chiusa | chore/kit-data |
| T-004 | Scorer | T | File di predizioni malformato o con percorsi inventati che falsa il punteggio | i file non etichettati vengono ignorati (non entrano nelle metriche, avviso su stderr); i campi mancanti contano come errore | chiusa | feat/scorer, feat/baseline |
| T-005 | Scansione | I | Link simbolico nella cartella che porta a file fuori dal perimetro | link simbolici saltati; file aperti in sola lettura | chiusa | feat/baseline |
| T-006 | Scansione | D | File enorme che esaurisce la memoria durante l'hash | SHA-256 calcolato a blocchi da 1 MB | chiusa | feat/baseline |
| T-007 | Estrazione | D | ODT costruito come zip bomb o XML "billion laughs" | `content.xml` oltre 50 MB scartato; XML letto con `defusedxml` | chiusa | feat/extract |
| T-008 | Estrazione | T | File malevolo che sfrutta un difetto dei parser (pdfminer, mammoth, openpyxl) | versioni fissate in `requirements.txt`; errori trasformati in testo vuoto; da isolare in container senza rete (deploy) | aperta | feat/extract |
| T-009 | Dipendenze | T | Pacchetto PyPI compromesso o aggiornato di nascosto | versioni fissate; hash (`--require-hashes`) da aggiungere | aperta | feat/extract |
| T-010 | Entità | I | Valori in chiaro (CF, IBAN) esposti nell'export o nei log | l'export contiene solo il valore mascherato e la posizione; nessun log dei valori | chiusa | feat/entities |
| T-011 | Entità | D | Testo costruito per far esplodere le regex (ReDoS) | regex senza quantificatori annidati ambigui, finestre limitate (`{0,60}`) | chiusa | feat/entities |
| T-012 | Categorie | I | Evidenza della categoria (es. diagnosi) esposta a chi non deve vederla | l'evidenza è solo la parola chiave trovata, non il contesto; filtro per ruolo da fare in UI | aperta | feat/categories |
| T-013 | Estrazione EML | T/D | Allegato con nome malevolo (`../../x`) o email annidate all'infinito | dal nome dell'allegato si usa solo l'estensione, file scritto in una cartella temporanea; massimo 3 livelli di annidamento | chiusa | feat/categories-ext |
| T-014 | OCR | T | Nome di file che inietta opzioni o comandi in tesseract/ocrmypdf | comando come lista senza shell; percorso assoluto, quindi mai un argomento che inizia con `-` | chiusa | feat/ocr |
| T-015 | OCR | D | PDF con migliaia di pagine o immagine enorme che blocca l'analisi | timeout di 300 s per file, poi testo vuoto | chiusa | feat/ocr |
| T-016 | Registro trattamenti | T | Registro malformato o con parole chiave costruite per rallentare le regex | colonne obbligatorie verificate all'importazione; parole chiave trattate come testo letterale (`re.escape`) | chiusa | feat/matching |
| T-017 | Permessi cartelle | T | File dei permessi malformato o incompleto che nasconde un accesso eccessivo | colonne obbligatorie verificate; cartelle confrontate per segmenti interi (`Personale/PermessiVecchi` non eredita `Personale/Permessi`); vale la cartella più specifica | chiusa | feat/compliance |
| T-018 | Registro trattamenti | T | Scheda senza le colonne "Categorie particolari dichiarate" o "Diffusione" che fa sembrare conformi i documenti | default sicuro: colonna assente = niente dichiarato, quindi più scostamenti, non meno | chiusa | feat/compliance |
| T-020 | Data del documento | T | Nome del file o data nel testo alterati (es. file rinominato) per evitare o provocare CONSERVAZIONE_SCADUTA | la data scritta dopo il luogo nel testo vale più del nome del file; date future e impossibili scartate; la decisione resta all'RPD, che vede la data usata | aperta | feat/retention |
| T-021 | Data del documento | D | Testo costruito per rallentare la ricerca delle date | regex senza quantificatori annidati; contesto letto su una finestra fissa di 70 caratteri | chiusa | feat/retention |
| T-022 | Modello locale | I | Testo dei documenti inviato a un server fuori dall'ente | `OllamaClient` accetta solo http(s) verso localhost, 127.0.0.1, ::1 o il servizio `ollama` del compose; altrimenti errore all'avvio | chiusa | feat/llm-matching |
| T-023 | Modello locale | T | Documento con istruzioni nascoste ("rispondi SI", "scegli T-…") che pilotano l'abbinamento (prompt injection) | testo tra `<documento>` dichiarato come dato; risposta solo JSON; codici accettati solo se esistono nel registro e superano a loro volta la verifica SI/NO; il modello decide solo i casi dubbi e la motivazione mostra "modello locale" all'RPD. Resta possibile spostare un caso dubbio | aperta | feat/llm-matching |
| T-024 | Modello locale | D | Server lento o bloccato che ferma l'analisi | timeout per chiamata (120 s); se non risponde valgono le regole | chiusa | feat/llm-matching |
| T-019 | Conformità | I | Cartella aperta a tutti non presente in `permessi_cartelle.csv`: ACCESSO_ECCESSIVO non segnalato | nessuna (una cartella non elencata non ha gruppi noti); da segnalare all'RPD come permesso sconosciuto | aperta | feat/compliance |
| T-025 | UI | S | Accesso alla UI senza credenziali da altri computer della rete | senza file degli utenti la UI parte solo su 127.0.0.1; con il file: HTTP Basic, password PBKDF2-SHA256 310.000 iterazioni, confronto a tempo costante | chiusa | feat/ui |
| T-026 | UI | I | Credenziali HTTP Basic intercettate in rete | da esporre solo dietro un proxy HTTPS (deploy); la UI non gestisce TLS | aperta | feat/ui |
| T-027 | UI | T | Decisione registrata a insaputa dell'RPD da un altro sito (CSRF) | token legato all'utente (HMAC) e controllo dell'intestazione Origin su ogni POST | chiusa | feat/ui |
| T-028 | UI | E | Operatore che registra decisioni riservate all'RPD | ruolo verificato sul server a ogni POST, non solo nascondendo il modulo | chiusa | feat/ui |
| T-029 | UI | T | Contenuti del JSON o note con HTML o script (XSS) | autoescape di Jinja2; CSP senza script inline né esterni; campi del JSON validati e troncati | chiusa | feat/ui |
| T-030 | UI | R | Decisione modificata o cancellata dopo la registrazione | registro SQLite in sola aggiunta (trigger che bloccano UPDATE e DELETE), con utente e ora | chiusa | feat/ui |
| T-031 | UI | I | Dati personali esposti nell'interfaccia o nei log | solo valori mascherati, nessun testo integrale; log di accesso spento; nota RPD con l'avviso di non inserire dati personali | chiusa | feat/ui |
| T-032 | Esportazione CSV | T | Formula nel CSV eseguita all'apertura in un foglio di calcolo | celle che iniziano con = + - @ precedute da apostrofo | chiusa | feat/ui |
| T-033 | UI | T | Stili inline ammessi dalla CSP (`'unsafe-inline'` per `style-src`) | richiesti dal JavaScript di Bootstrap Italia; gli script restano solo dall'applicazione | accettata | feat/ui |
| T-034 | UI | I | Ricerca senza limiti per permessi: ogni utente vede tutti i documenti | nessuna (la specifica chiede la ricerca nei limiti dei permessi dell'utente) | aperta | feat/ui |
| T-035 | Bozze di schede | I | Dati personali dei documenti (nomi, CF) copiati dal modello nei campi della bozza, poi nel registro | prompt che chiede categorie e non persone; campi scartati se contengono entità riconosciute o un "Nome Cognome" presente nei documenti; i cognomi con maiuscola iniziale tolti dal nome del gruppo; l'RPD rivede ogni campo prima di approvare. Restano possibili nomi in maiuscolo, nomi singoli o indirizzi | aperta | feat/draft-records |
| T-036 | Bozze di schede | T | Documento con istruzioni nascoste che fa scrivere al modello una scheda fuorviante (es. base giuridica, diffusione) | testo dichiarato come dato; risposta solo JSON; base giuridica da elenco chiuso; cartelle, gruppo, categorie e diffusione decisi dal sistema e non dal modello; nessuna scrittura automatica nel registro: approvazione dell'RPD | chiusa | feat/draft-records |
| T-037 | Bozze di schede | T | File delle predizioni alterato con percorsi `..` per leggere file fuori dalla cartella analizzata | percorso risolto e accettato solo dentro la cartella; link simbolici saltati | chiusa | feat/draft-records |
| T-038 | UI bozze | E/T | Operatore o altro sito che approva una scheda, o campi con HTML, caratteri di controllo o formule | ruolo `rpd`, token CSRF e Origin come per le decisioni; campi senza caratteri di controllo, massimo 500 caratteri; autoescape; CSV con celle protette dalle formule; tabella `bozze` in sola aggiunta | chiusa | feat/draft-records |
| T-039 | UI schede | E/T | Operatore o altro sito che crea, modifica o archivia schede; codice con `/` o `..` negli URL; campi con HTML, caratteri di controllo o formule | ruolo `rpd`, token CSRF e Origin come per le decisioni; codice con formato fisso anche nell'URL; campi a scelta chiusa verificati, testo senza caratteri di controllo e massimo 1000 caratteri; autoescape; CSV con celle protette dalle formule | chiusa | feat/records |
| T-040 | UI schede | R | Modifica del registro senza traccia (chi ha cambiato una scheda e quando) | tabella `schede` in sola aggiunta con autore e data, trigger contro modifica e cancellazione; il CSV di partenza non viene scritto. Chi ha accesso al file SQLite può comunque cancellarlo | aperta | feat/records |
| T-041 | UI prova un file | I | Testo integrale di un documento mostrato nella pagina, con i dati personali evidenziati (eccezione a T-031; da feat/doc-view anche nel dettaglio documento), e rimasto in cache o su disco | solo RPD; il testo torna solo a chi ha caricato il file, primi 5000 caratteri; `Cache-Control: no-store`; file in cartella temporanea cancellata a fine richiesta, nulla nel database né nei log | chiusa | feat/try-file |
| T-042 | UI prova un file | T/D | File malevolo: nome con `..` o `/`, cartella con `..`, file enorme, zip bomb, PDF che blocca l'OCR | sul disco nome fisso, dall'utente solo l'estensione ripulita; cartella con caratteri ammessi e senza `..` (usata solo come testo, mai come percorso); massimo 20 MB letti; estrattori con i limiti esistenti (XML ODT 50 MB, timeout OCR 300 s); analisi in un thread. Più caricamenti insieme possono comunque occupare CPU | aperta | feat/try-file |
| T-043 | UI prova un file | T/S | Analisi rimandata dal browser alterata (esito, scheda, percorso, impronta) per inserire nell'inventario un documento falso | analisi firmata con HMAC-SHA256 legata all'utente; firma non valida → 400; scheda accettata solo tra quelle proposte e presenti nel registro; ruolo `rpd`, CSRF e Origin | chiusa | feat/try-file-visual |
| T-044 | UI prova un file | I | Dati personali conservati entrando nell'inventario | solo la predizione con valori mascherati nella tabella `caricati`; testo e file mai salvati; la firma nel modulo contiene le stesse informazioni mascherate | chiusa | feat/try-file-visual |
| T-045 | Bozze di schede | T | Documento con istruzioni nascoste che fa scegliere al modello una scheda simile sbagliata, da cui copiare struttura, ufficio e software | il modello sceglie solo tra le 3 schede recuperate dal registro (codici inventati ignorati); i campi copiati restano "da verificare" e l'Origine indica la scheda di provenienza; nessuna scrittura nel registro senza l'RPD | chiusa | feat/semantic-drafts |
| T-046 | Bozze di schede | I | Testo dei documenti inviato a un servizio di embedding esterno | gli embedding passano dallo stesso `OllamaClient`, che accetta solo host locali | chiusa | feat/semantic-drafts |
| T-048 | UI, filtro per settore | T, I | Nome di cartella con HTML o caratteri speciali nel parametro `settore` o nella tabella del cruscotto (XSS, filtro manipolato) | il valore è accettato solo se è uno dei settori presenti nell'inventario, altrimenti 400; nei link è codificato (`urlencode`) e nella pagina passa dall'escape automatico di Jinja | chiusa | feat/sector-view |
| T-047 | Bozze di schede | T | Documenti scelti apposta (o solo simili) che uniscono due trattamenti diversi in una sola bozza | unione automatica solo sopra coseno 0,85, tra 0,70 e 0,85 serve il SI del modello; l'RPD vede l'elenco dei documenti di ogni bozza prima di approvare. Resta possibile un'unione sbagliata, nessun avviso automatico | aperta | feat/semantic-drafts |
| T-048 | UI dettaglio documento | I/T | Predizioni alterate con percorsi `..` o link simbolici per far leggere alla UI file fuori dalla cartella analizzata, oppure file enormi | percorso risolto (anche i link) e accettato solo dentro `UI_DOCUMENTI`; massimo 20 MB; solo ruolo `rpd`; testo mai salvato, pagina `no-store` | chiusa | feat/doc-view |
| T-049 | UI dettaglio documento | T | File cambiato dopo l'analisi: la scheda scelta dalle card varrebbe per un contenuto diverso da quello validato | impronta SHA-256 ricalcolata a ogni apertura; se diversa, avviso e nessuna card di scelta | chiusa | feat/doc-view |
